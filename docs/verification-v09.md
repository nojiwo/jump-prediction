# v0.9 検証報告 — 2026-10-13

## 実装上の変更点

### 部分下書きの復元

以前のReact画面では、`prediction_draft_items` に先頭数作品のみが保存された場合、GET応答のその配列をそのまま全候補 `order` に設定していたため、再読み込み後に残りの対象作品が消え、正式提出できなくなる問題があった。

- `src/core/draft-order.ts` の `restoreDraftOrder` で「保存済みの並び」＋「凍結対象の残り」を一意に結合する。
- サーバーは下書きに対して、選択された先頭部分をそのまま保存する。正式提出のデータを変更しない。
- GET `/api/prediction?issue=...` は `draft_input_mode` を返し、途中で個人設定を変更してもその号の入力途中の方式を保持する。
- 管理者の掲載順下書きも候補を復元し、突然休載した作品を除外。掲載予定外の作品は先頭の下書きに残してよい。
- 突発休載を解除した際、対象作品を画面の候補へ戻す。
- 正式提出後に別の下書きがある場合、閲覧専用画面は**必ず正式提出済みの順序**を表示する。「予想を編集する」を押したときにだけ、途中までの下書きと残りの候補を復元する。
